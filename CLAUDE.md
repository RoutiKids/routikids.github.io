# Routikids

Single-page app (`index.html`) served via GitHub Pages from `main` at **https://routikids.github.io/**. Families share the same URL; each device keeps its routine in `localStorage`, and paired devices sync through Firebase (below).

## Old address

The app used to live at `fabiofialho1.github.io/rotina-infantil-na-tv/` (repository `fabiofialho1/rotina-infantil-na-tv`), which now only hosts a redirect page. It forwards each device's `rotina*` localStorage keys here in a `#migrate=` URL fragment (and keeps `?parear=CODE`). The small script at the top of `<head>` imports that data when this device has none of its own and removes the fragment: keep it, and keep the `rotina*` key names.

## Language conventions

- Code comments: **English**.
- Commit messages, PR titles/descriptions and GitHub comments: **English**.
- User-facing UI text lives in the `I18N` dictionary in `index.html`, in **Portuguese (pt-BR), English and German**; always add a new text to all three and use `tr('key', {vars})` (static HTML: `data-i18n`, `data-i18n-html`, `data-i18n-placeholder`, `data-i18n-title`). The translation function is `tr`, not `t`, because `t` is used everywhere for tasks.
- The language is per device (picker on the welcome screen and in settings; else the device language for new devices; devices that already had a routine default to Portuguese).
- UI texts never use dashes (—, –, or " - ") as punctuation: use a comma, colon, period or parentheses instead. Ranges such as `07:00 – 07:30` or `seg–sex` are fine.
- The app is called **Routikids** (`APP_NAME`), with a translated tagline (`tagline` key).

## Versioning

- On every change to `index.html`, update the `<meta name="app-version" content="Versão do código: YYYY-MM-DD HH:MM">` tag in `<head>` (keep that exact text: older app versions search for it to detect updates; the settings footer shows it translated) to the current date/time in Europe/Berlin (the owner lives in Germany), followed by ` · PR #N`, the number the pull request carrying the change will get (the next issue/PR number of the repository; check it after opening the PR and fix it if it differs). The date/time part must stay right after "Versão do código: " (the update check and older versions read only that part); the settings footer shows both, e.g. "Versão do código: 2026-10-11 10:30 · PR #41". The owner uses it to confirm on the TV that the latest version is live, and the app compares it with the published `index.html` to detect updates (banner + automatic reload at a safe moment), so it must always move forward.

## Cloud sync (pairing)

- Devices pair with a 6-digit code (or QR link `?parear=CODE`) and then share one "house" in a Firebase Realtime Database, via its REST API (no SDK). Live updates come over Server-Sent Events.
- Each device signs in anonymously through the Firebase Auth REST API (no accounts). Only devices listed in `houses/<id>/members` can read or write that house, so removing a member cuts its access for real. Config lives in `houses/<id>/data`.
- `CLOUD_DB_URL` and `FIREBASE_API_KEY` in `index.html` configure it (the API key is public by design); an empty URL hides the pairing section (the app then works on a single device).
- New devices (nothing saved, not paired) see a welcome screen with a test/privacy note, routine templates (`ROUTINE_TEMPLATES`) and a pairing-code field. On TVs the code field comes first (with a QR code and the address to open the app on the phone) and the templates stay behind "Sem celular? Configurar aqui na TV"; existing devices never do.
- Phone-first setup: after "Começar" on a non-TV device, the "📺 Agora leve para a TV" screen (`openTvSetup`) shows the address to type on the TV, a pairing code that renews itself while open, and per-brand steps (`renderBrandGuide`); it turns into "TV conectada" when `announceNewMembers` sees the TV join. It also opens from settings. The "📖 Guia rápido" (`openGuide`) explains the app and the same TV steps.
- Security rules live in `database.rules.json` and must be pasted into the Firebase console whenever they change. Anonymous auth must stay enabled, with automatic cleanup of anonymous accounts **off**.
- A device only drops its pairing after two database refusals at least 15s apart, and only discards its anonymous identity when Auth says it is gone (not on generic 400s). Key events go to a per-device "Histórico da conexão" (localStorage) shown in the sync section, to diagnose lost pairings.

## Today's progress and backup

- `initSchedule(cfg)` keeps today's progress by default: done tasks keep their real times and outcome, the current task keeps its start and extensions, and new tasks are fitted in (`mergeDayProgress`). It runs when a config arrives from another device, after a settings save and on load (from `rotinaDayState_v1`, saved each second by `saveDayState`). A new day passes `{ fresh: true }`.
- "Testar agora" is shared: it sets `testStartedAt` in the config (so it reaches every paired device, with no database rule change) and today's tasks run 1 minute each from that moment. Changes during a test keep it running; "Sair do teste", the test ending or 2 hours passing clear it, and the real day comes back with its saved progress (test progress is never saved). Backups never carry `testStartedAt`.
- Settings has "💾 Salvar cópia" / "📂 Restaurar cópia" (a JSON file with `kind: 'backup'` and the config); the welcome screen also offers the restore, for a wiped browser. A restore is pushed to the paired devices.
- Today's progress is shared too: a tap that changes it (Já terminei, Começar, the "Terminou?" answer, reordering, the deadline) calls `progressAction()`, which publishes the day snapshot to `houses/<id>/progress` (`state`, `seq`, `updatedAt`, `by`). Other devices apply it through `initSchedule(TASKS, { progress })` when its `seq` is higher (numbers, not clocks, because device clocks differ). Automatic steps (the dialog timeout, catching up) run on each device by itself. If the database refuses it (rules not updated), sharing stops quietly for that session and the pairing is untouched.

## Children

- The config has `children` (`{ id, name, icon, color, picturesOnly }`) and every routine has a `childId`. `normalizeConfig` turns older configs (a single `childName`, routines without `childId`) into one child `c1` that owns every routine; `childName` stays equal to the first child's name for older app versions. It runs on load, on configs received or restored, and on templates.
- One day per child: the schedule engine keeps the day it works on in globals (`tasks`, `pointer`, `awaitingStart`, ...) and draws into swappable element refs (`heroEl`, `timelineEl`, ...). Each child has a slot (`SLOTS`); `withChild(slot, fn)` swaps that child's day and elements in (`saveDay`/`loadDay`/`useView`), runs `fn` and swaps back. Between calls the globals hold the first child's day. A new per-day global must be added to `freshDay`, `saveDay` and `loadDay`. Config changes call `initAllChildren()`; the 1-second loop is `renderAll()`.
- With two or more children the main screen is hidden and `buildPanels()` makes one column per child in `#kids-grid` (sizes follow the column via `--w`); each column's buttons act on its child. The "Terminou?" dialog is shared: one child's question at a time (`confirmOwner`). The automatic reload waits until no child is mid-task, and a shared test ends when every child's test has ended. Confetti stays inside the child's column.
- Settings edit one child at a time (tabs, up to 4 children): name, picture, colour, "só figuras" (the list shows only pictures), "mostrar a rotina" (`hidden`), and only that child's routines and weekly table. A hidden child keeps its routines but gets no slot (no column, sounds or questions); at least one child is always shown.
- Each column is filled with the child's colour (coloured header, tinted cards; with a single child shown, the main screen gets the same colours through `html.solo` and `--c`) and has its own ◀ ▶ arrows when no task is running. "Já terminei" is a round ✔ next to the minutes, the minute blocks get a full-width row, and tasks done before the last one collapse into a row of small pictures (`.kid-trail`) so the list fits without scrolling (scrolling with a TV remote is unreliable).
- The page declares `color-scheme: light dark` (meta and `:root`) although it only has light styles: some TV browsers darken pages on their own, and those built on Android WebView skip pages that say they handle dark mode. Keep every background explicit so the page stays light. Routine overlap warnings only compare routines of the same child.
- Today's progress is kept per child: locally in `rotinaDayState_v2` (`{ childId: snapshot }`, migrated from `rotinaDayState_v1`) and in the database at `houses/<id>/progress/<childId>`. A device whose progress is ahead of the stored entry publishes it when it reads the house, so a device joining mid-day starts from where the others are.
- Per child, "Terminou?" with no answer follows `confirmDefault`: `yes` (count as done, the old behaviour), `more` (extra time once, then closes as late) or `wait` (no timer, until the routine's deadline, then closes as late); `confirmSeconds` (10/20/30/60) and `extraMin` (3/5/10, also used by the "Não" button).
- A cloud read that started before this device's last config push is ignored for the config (`lastConfigPushAt`), so it cannot undo a save that was just made.
- Feedback uses pictures, not words: extra time sends the child's `runner` (🏎️ 🚀 🐕 🐇, chosen per child) racing across their column with a synthesized "vroom"; a task finished late pops the late icon with a soft sound. There is no text banner or speech synthesis (it was hard to understand). "Já terminei" is a box to tick ("Terminei") next to the minutes, in a column and on the single-child screen alike (`#finish-early-btn` also has the `.kid-finish` class; `#hero` sets `--w`), shown ticked for 0.6 s before the task closes.

## Forecast, skipping and sound

- Times shown are forecasts: the list refreshes them every second (`refreshStepTimes`), and while the next task waits for "Começar" past its time they move on from now (`forecastTimes`). A time that differs from the plan shows in red (later) or green (earlier) with the planned one in brackets (`stepTimeHtml`, `timeShiftHtml`); the same goes for the current task's "até" and for the routine's expected end (`showForecastFor`: "🏁 Término previsto" in the footer next to the clock on the main screen, "🏁" in a column's header). The deadline ("Horário limite") is only a routine setting now: it is no longer shown or adjustable on the main screen (`#limit-control` stays in the DOM, hidden, because the engine still reads its elements).
- "⏭️ Ignorar hoje" skips a task for today only (`askSkip` asks first, then `skipTask`): the current one closes at once with no star or turtle; a later one gets `userSkipped` and no time, and is passed over when its turn comes (`passSkipped`). Every skip can be undone with ↩️ in the list: a later one comes back (`unskipTask`), one already passed comes back as the next task after the running one of its routine, or as the current one waiting for "Começar" (`restoreSkipped`, `canRestore`). Skipped tasks are never folded into a column's trail, and the ↩️ shows even in "só figuras" lists. `userSkipped` travels in the day snapshot and survives `mergeDayProgress`.
- After a task closes ("Terminei", or skipping the running task), the next task waits for "Começar" only if it belongs to the same routine (`afterTaskClosed`). A new routine set to "⏰ Horário fixo" never waits for "Começar": it starts at its own time, and until then the screen shows the wait between routines. `renderMain` also repairs a saved day where the next routine was left waiting.
- "Início da rotina" (per routine, `startMode` in the config, `routineStartMode`): "⏰ Horário fixo" (default, saved as no value) or "▶ Botão Começar" (`'button'`; the afternoon template uses it). A button routine waits for "Começar" at its time with no time counting; if nobody starts it before the next routine's time it is left out of the day (its tasks get `outcome: 'skipped'`). For every routine: "▶ Começar agora" any time before it (`startRoutineNow`), "↻ Começar agora" during its first task (restarts the plan from now), "⏰ Adiar 10 min" (`delayStart`, +10 per tap) and "↩️ Voltar para HH:MM" (`undoDelay`). The moved start is `startShift` on the routine's first task (`effectiveStart`, `blockShift`); the list, "até" and the expected end compare with the moved plan, and while a routine waits for its start the plan moves on with now (`shownShift`), so waiting shows no red. `startShift` and `started` travel in the day snapshot. During a test ("Testar agora") every routine counts as "Horário fixo" (`routineStartMode` checks `testMode`), since the test runs them back to back. A test on a day with no routines (e.g. a weekend with weekday routines) runs the next day that has some (`nextRoutineDayTasks`, in `initSchedule`); before, it ended at once and "Sair do teste" flashed and went away.
- "🔄 Reiniciar rotina" (`askResetRoutine`, asks first; `resetRoutine`): shows while a routine is under way (started, a task done, or its task running). All its tasks are pending again in planned order, its start mark is cleared; a "Botão Começar" routine waits for "Começar" (or its time), a "Horário fixo" one waits for its time or, past it, runs from now.
- A task whose time went by with no device open (or a routine left out) is passed over silently (`catchUpToNow`, `outcome: 'skipped'` without `userSkipped`, `isPassed`). The list shows it with a faded ❔ and ✏️: tapping ✏️ asks how it went (`askMarkPassed`, a dialog with one button per answer, `appChoose`): "Feita no prazo" (star sticker), "Feita com atraso" (turtle) or "Não foi feita" (becomes `userSkipped`, ⏭️). Afterwards ↩️ works as for any done or skipped task. The answer travels in the day snapshot like any outcome.
- "↩️" on a task already done (⭐ or turtle) undoes it (`askUndoDone`, asks first, then `restoreSkipped`, the same path as a skipped task, `canRestore`/`isDone`): it comes back right after the running task of its routine, or as the current one. A routine's start mark (`started`, `startShift`) stays with whichever task is first in the routine when tasks are reordered (`blockMark`, `keepBlockMark`, used by `restoreSkipped` and `postponeTask`); a routine's first task brought back this way runs from now.
- Task controls under the current task: "⏸️ Pausar" (a direct button) and "⋯ Opções" (a menu, `.task-menu`, `updateTaskMenu`; it opens upwards, a choice or a tap elsewhere closes it), in two parts: "Esta tarefa" with "↪️ Depois da próxima" (`postponeOne`: swaps with the next task, only offered when it differs from the next item), "⤵️ Para o final da rotina" (`postponeTask`: to the end of the routine, the next one waits for "Começar"), "🔁 Recomeçar o tempo" (`restartTask`) and "⏭️ Ignorar hoje"; and "Rotina inteira" with "🔄 Reiniciar rotina", set apart. The menu's buttons are the old per-view buttons (`skipBtn`, `postponeBtn`, `resetRoutineBtn`) plus the new ones found through `extrasEl`.
- "⏸️ Pausar" (`togglePause`, `canPause`, `isPaused`): the pause lives on the current task (`pausedAt`, carried in the day snapshot and merged for the current task), and while paused `applyPauseShift()` moves the task's start (and the later tasks) along with the clock on every tick and when a saved or shared day is loaded, so the time left stays put, nothing is closed or skipped, and the paired devices pause too. "▶ Continuar" resumes (and fits the "✂️" tasks). Closing, skipping, postponing or restarting a task clears its pause. A pause doesn't make a task late.
- Settings are in five tabs (`#settings-tabs`, `.settings-pane[data-pane]`, `showSettingsTab`): 📋 Rotinas (child switch `#routine-child-switch` plus the routine editor), 👧 Crianças (`#children-section`: profile, pictures, stars and goals), 🔊 Sons (the family audios `#audio-section`, then each child's sounds `#child-sounds-section` with its own child switch `#sound-child-switch`: well done, routine complete, goal reached when stars are on, hurry; each with "▶️" (`.sound-try`) that plays what the child would hear now, a surprise drawing one, even with the sound off, and names it in `#sound-now`), 📱 Aparelhos ("Levar para a TV", pairing `#sync-section`, backup) and ⚙️ Geral (language, guide, on-time/late pictures, stats, notes, version). `openSettings(tab)` always opens on Rotinas unless told (the pairing link opens Aparelhos). The tabs and Cancel/Save stay in view while the card scrolls (sticky). With more than one child, "Rotinas de:" chips choose whose routines are shown, the routine card takes that child's colour (`--rc`) and its title reads "🦄 Nina › 🌞 Manhã"; "✏️" opens the child's profile. Tabs, child chips and "+ Nova rotina" don't count as unsaved edits.
- "📅 Mudar só um dia" (routine card, `#routine-oneday-btn`, `renderOneDay`, `nextDatesOf`): picks one of the next dates (up to 6) on which a weekly routine runs and makes a one-day version: an independent copy with `onDate` (YYYY-MM-DD) and `baseId` (the routine it replaces), shown as its own tab ("🎈 Sábado · Sáb 17/10", dashed) with a note, no weekdays and no delete. "🚫 Sem esta rotina neste dia" (`off`, no tasks) removes the routine that day; "↩️ Voltar ao normal neste dia" deletes the version. Days are built by date (`buildTasksForDate`, `activeRoutineIdsForDate`, `dateInDays`, `dateKey`), so today, the browsed days and "tomorrow" all use it. `normalizeConfig` drops past versions and keeps them out of `weekSchedule`; deleting a weekly routine drops its versions. Changes to the weekly routine made later don't reach a version (it's a copy).
- "📋 Copiar tarefa existente" (next to "+ Adicionar tarefa", `#settings-copy-task`, `#copy-task-list`, `copyableTasks`): lists the tasks of the other routines (the selected child's first; one per picture and name; none already in this routine), with duration and routine; a tap adds an independent copy at the end of this routine (picture, name, duration, sound, "✂️"), chained.
- Routine editor (settings, `#routines-section`): routine tabs, then one card for the selected routine (`#routine-card`: title `#routine-card-title`, then `#routine-details`, a folded `<details>` with name, picture, weekdays as toggles `#routine-days` / `.day-toggle` plus "Todos os dias", "Início da rotina", the deadline as a time field `#routine-limit-input`, and delete; then "Tarefas: <routine>" and the task rows). Switching routines folds the details; a new routine opens them. "+ Nova rotina" opens `#template-add-row` (blank or a template). Clashes between routines of the same day show as red day toggles plus `#conflict-warning`.
- A routine's tasks always follow one another in list order with no gap or overlap (the day runs them chained). The settings editor keeps that (`chainDraftTasks`): the first task has a time field (`.task-start-input`, the phone's time picker) that moves the whole routine; every task has a duration "− 10 min +" (`.dur-btn`, `adjustDraftDuration`, `stepDuration`: 1-minute steps up to 5, then multiples of 5) and the later tasks move along; moving ("↑ Subir" / "↓ Descer", words on grey pills, kept apart from the round time buttons), adding or removing keeps the routine's start; durations are at least 1 minute. There is no "time arrow step" setting any more. `normalizeConfig` repairs saved routines the same way (`chainConfigTasks`, `spanMinutes`: a task whose end is a little before its start gets 5 minutes). There is no "adjust the next task" option any more.
- Delays are made up only with the tasks the parents marked "✂️ Encurtar se atrasar" (`flex` in the config, a checkbox per task): `fitFlexibleTasks()` shrinks them a minute at a time (roughly in proportion, each down to half its planned time at most) until the routine is back on its planned end; what's left pushes the end (red forecast). With none marked, delays just push. Durations restart from the plan on each fit (extra time, "Começar", a task closing, a skip), so time gained is given back. A shortened task shows ✂️ in the list. The routine's deadline is no longer used to compress.
- The time bar under the current task (`buildSegments`, `updateSegments`): up to 30 minutes, one numbered block per minute; a task of 31 minutes or more gets `.long` and `.tick-rows`: one row per hour (labelled 1h, 2h…) of 60 thin 1-minute ticks (`.seg.tick`, a gap every 10 via `.ten`), so a tick is always one minute and the bar fits (rows get lower when there are many). Same in the single view, the children's columns and on phones.
- A list longer than its space (the side list on the TV or a child's column) scrolls by itself when the current task changes: the task before the current one goes to the top (`timelineEl.dataset.scrolledTo`, once per task so a hand scroll stays); while the first task runs the list stays at the top with the routine title.
- The clock, the expected end and the sound button sit at the top right on the TV and computer (one child or several), so nothing covers the list; on phones they are a row under the title.
- Task pictures: `EMOJI_PRESETS` (about 70, by theme) plus a field for any typed emoji. Every other picture picker (child, runner, routine complete, on time, late, routine icon) has the same field (`customEmojiField`, `onCustomEmoji`), and `normalizeConfig` cleans all those pictures with `cleanEmoji`. In settings a task's list stays closed until its picture is tapped (`openPickerIdx`, one at a time; a new task opens with it). `cleanEmoji()` keeps only non-ASCII characters (no letters or markup), applied when typing and in `normalizeConfig`.
- Per child `doneIcon` (`CHILD_DONE_ICONS`) and `doneAudio`: when a routine completes, `celebrateRoutine()` pops the picture big with balloons and confetti and plays the family audio or a fanfare; the card shows it when the day's routines are done or between routines.
- The mouse wheel over the dark area around a card (settings, welcome, guide, TV setup) scrolls the card.
- Another device's sound can be switched from the device list (📱 Aparelhos, `.cloud-sound-btn`): each device shares `sound` and `soundBlocked` in its member record (`publishSoundState`, separate from the join record so pairing works with older rules); a command writes `sound` plus `soundCmdAt` (`sendSoundCommand`), and the device applies each command once (`syncSoundWithHouse`, last one kept in `rotinaSoundCmdAt_v1`). Turned on without a tap, a browser may hold the sound back: the device shows the balloon and the phone says it needs a tap (`watchSoundUnlock`). Each device keeps its own sound. The rules allow `sound`, `soundBlocked` and `soundCmdAt` under `members/$uid`.
- The sound choice is remembered (`rotinaSoundOn_v1`). After a reload the browser may hold sound back (`soundBlocked`): the balloon shows, and any tap or key press brings the sound back. The app no longer reloads itself periodically, only for a new version at a safe moment, since each reload can cost the sound.

## Stars and goals

- Per child, off by default: "⭐ Estrelas e metas" in the Crianças tab (`stars`, `goalDayPct` and `goalWeekPct`: 50 to 100% of the tasks on time, 0 = none; `bonus` default on, plus `goalAudio`). A task done on time is worth ⭐ (`starsOf`), one finished well before its end ⭐⭐ (`finishedEarly`, set in `markTaskDone` as `t.early`): at least 20% of its time left (and 1 minute) but not done in less than half its time, so rushing gets no bonus. The bonus can be off for the child or per task (`noBonus` in the config, "⚡ Bônus por terminar antes" on each task row, only shown with stars and bonus on). Late tasks keep the turtle and get no star; with stars on, the on-time sticker stays and the stars earned show next to it (🐆⭐ or 🐆⭐⭐, `starBadge`) in the list and in a column's trail (the child missed the leopard when it was replaced by a star). `early` travels in the day snapshot and survives `mergeDayProgress`; undo and restore clear it.
- Goals are a share, not a star count, because the number of tasks changes: each day the daily goal becomes `dayTarget()` = the share of the day's tasks that count (all but the ones skipped for the day, `userSkipped`, which includes "Não foi feita"), rounded up, at least 1; the weekly goal `weekTarget()` = the share of the week's tasks (today live, the other days Monday to Sunday from the routines). ⭐⭐ counts double, so finishing early helps reach it. Configs saved with star goals (`goalDay`, `goalWeek`) are converted by `goalPct` in `normalizeConfig` to the share of the child's usual tasks they stood for (rounded to 10%, 50 to 100). The settings show the share of tasks on time over the last two weeks (`recentOnTimeShare`).
- The routine title shows "⭐ 5 de 8" (`goal-pill`). At the start of each routine (its first task running for less than 2 minutes, once per routine and day: `maybeShowRoutineIntro`, called from `render`) a card covers the hero for 10 s (`showGoalCard('start')`, `goalCardHtml`): a greeting, a game-like map (one stop per star of the day's target, at most 10, the child's picture on the last stop reached, 🏆 at the end), the week's bar and the rule. Reaching a goal (`checkGoalReached`, also for progress from another device) shows the card as `won` with the goal sound and balloons; after the day's last routine the card shows the day's stars (`'end'`). The card's font size follows the hero's size (em units), so it fits a child's column; a tap closes it.
- History: a summary per child and day (`daySummary`: `s` stars, `o` on time, `e` early, `l` late, `k` skipped, `u` time) is written by `recordDaySummary` from `saveDayState` (never in test mode), kept in localStorage (`rotinaHistory_v1`, 120 days) and, when paired, at `history/<houseId>/<childId>/<YYYY-MM-DD>` (members only, see `database.rules.json`; outside `houses/` so the live house stream stays small). `syncHistory` (on house updates, at most every 30 minutes, and on a new day) downloads the days, keeps the newest record of each day and sends the ones not sent yet (`up`). The week (Monday to Sunday) = earlier days from the history + today live (`weekStars`). "Delete the family's data from the cloud" also deletes `history/<houseId>`.
- Not built yet (next steps, agreed with the owner): prize tasks (a task marked "🎁 prêmio" tied to the daily goal, unlocked the next day, or to the weekly goal, Monday to Saturday for a Sunday prize; shown as a closed gift until then, and replaced by another activity if the goal was missed), then a challenge with double stars for tasks that are often late (from the history).

## Family audios

- Settings has "🎙️ Áudios da família": record in the browser (`MediaRecorder`, 32 kbps, at most 15 s with a countdown) or send a file (`audio/*`), then rename, play or delete. At most 20 (`MAX_AUDIOS`); a sent file up to 290 KB (`MAX_AUDIO_BYTES`, about 18 s of a 128 kbps MP3; its base64 stays under the rules' 400 000 characters), and all audio copies on a device up to about 3.5 MB (`MAX_AUDIO_LOCAL_CHARS`, localStorage holds about 5 MB). Changes save at once (`saveAudioList`), not with "Salvar", and never mark the settings as edited.
- The config only has the list, `audios: [{ id, name }]`. The sound is stored apart at `audio/<houseId>/<audioId>` (`data` in base64, `mime`, `updatedAt`; members only, see `database.rules.json`), so the live house reads stay small. A new audio goes up before the config that names it. Each device keeps a copy in localStorage (`rotinaAudio_v1_<id>`, with `up` = already in the cloud); `syncAudioCache()` downloads missing ones, retries failed uploads and drops copies no longer on the list. Without pairing, audios stay on the device.
- Uses: a task's start sound (`sound: { type: 'family', id }`), and per child `cheerAudio` (instead of the applause for a task on time), `hurryAudio` (instead of the "vroom" with the runner), `doneAudio` (routine complete) and `goalAudio` (goal reached). Cheer, done and goal can be "🎲 Surpresa" (`'*'`): each time one audio of the child's pool (`cheerPool`, `donePool`, `goalPool`, chips under the select, none marked at first; "Sorteia entre: …" lists them, none = the default sound) is drawn, never the same twice in a row (`childAudio`). A family audio that fails to play is noted in the connection log (`sound_failed`). A task's own sound (in the routine editor) plays when the task starts; the sounds for a task done and a routine done are the child's. A missing or unplayable audio falls back to the default sound.
- Backups carry the audio data (`audioData: { id: { data, mime } }`); a restore puts it back and sends it to the paired devices.

## Back button

- While a card or dialog is open (`BACK_LAYERS`: app dialog, guide, TV setup, settings, welcome), one extra history entry is kept (`syncBackGuard`, driven by a MutationObserver on the overlays' style). The phone's Back pops it and closes the card on top (`closeBackLayer`): settings with unsaved edits ask first (`leave_unsaved_q`); the welcome card stays (Back just keeps the app open). Closing a card with its own button removes the entry (`history.back()`, ignored by the popstate handler). With nothing open, Back leaves the app as before.
- `dropPairParam()` removes `?parear=` from the address when the pairing link is read and again after Back returns to the entry below a card.

## Usage statistics

- Anonymous and on by default, with an opt-out in settings ("📊 Enviar estatísticas anônimas de uso", `rotinaStatsOff_v1`). `sendStats()` writes one record per device per day at `stats/days/<YYYY-MM-DD>/<random id>` (`rotinaStatsId_v1`, never linked to the house or the auth identity): `k` kind of device, `p` paired, `c` children shown, `l` language, `v` app version, `d` tasks done today (test runs excluded), `r` routines with tasks, `t` used with a TV (this device is one, or it is paired with one), `u` time (`r` and `t` since 2026-10-09). It writes 20 s after opening, every hour, and 1 s after a task is done (at most every 2 minutes). Written without signing in; the rules (`stats` in `database.rules.json`) only accept that shape, never deletes, and let anyone read the numbers.
- The demo page (`demo/index.html`) writes `stats/demo/<YYYY-MM-DD>/<id>` with the same id as the app in that browser (and the same opt-out): `l` language, `s` furthest second of the video reached, `e` got to the end (95%), `u` time; sent 3 s after opening, every 10 s of video, on pause, at the end and when the page is hidden. The day's furthest point is kept on the device (`rotinaDemoSeen_v1`).
- `stats.html` (not linked, `noindex`) is the owner's summary: the week step by step (opened the demo, started the video, watched to the end, opened the app, has a routine with tasks, used with a TV, did tasks), then per day for the last 30 days the app (devices, kinds, paired, with a routine, with a TV, devices with tasks, total tasks, languages) and the demo video (opened, started, to the end, also opened the app, languages).
- Anything new that is collected must be described on the privacy page, with a dated line in its change history ("Histórico de mudanças").
